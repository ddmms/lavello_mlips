## 2026-05-11 - [String Checks before Regex for Large Files]
**Learning:** Evaluating complex regular expressions (like parsing Eigenvalues, dipoles, quadrupoles) against massive multi-megabyte plain-text blobs (`orca.out` files) is a severe performance bottleneck. Python's `in` string operator acts as a highly optimized C-level search (Boyer-Moore-Horspool) which is magnitudes faster than pushing the entire multi-line block through the regex engine when no match exists. Additionally, modifying large text blocks with transformations like `.lower()` allocates massive copies in memory and neutralizes any speed gain.
**Action:** Always insert precise, literal string checks (`if "Keyword" not in txt`) *before* invoking regex `search` or `finditer` on massive text fields. Only apply `.lower()` to the small extracted matching groups, not the original text block.
